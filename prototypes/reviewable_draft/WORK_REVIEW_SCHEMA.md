independent source-meaning assessment. Workers and tests have ZERO live HTTP, model,
metadata, service, installation, configuration or delegation allowance. All older
allowances stay closed. This additive collector changes no historical source/evidence,
production behavior, model or runtime configuration.

fixed order, once each: `front_loaded_timing`, `partial_coordination_retracted`,

and a newline to the existing system content. Keep the API format, user message and

`freeze(output, identity)` performs no HTTP and exclusively creates a new directory.
It requires clean, exact committed source with preserved transitive import baselines
and the HTTP helper's independent early import baseline. Accepted source hashes and
prospective criteria are fixed. Source, tests, declarations, original forty-input bytes,
complete snapshots, exact wires, model identity, settings and all three packet/request/
snapshot/generation bindings are inventoried. `_validate(output, pin)` reproduces these
bytes and checks every slot, including unsent slots, before launch and at later gates.
`_source(candidate)` accepts only an exact ancestor commit with identical current files.
Closed fixtures work in depth-one CI without fetching historical Git objects. Failed or
existing freezes/results cannot be overwritten; traversal and symlinks are refused.
No imported clocks, baselines, request bodies, transport policies or globals are patched.

`run(output, approval, pin, assess)` is the only live API. Nonblank approval is audit
context, not authentication. The independent child policy permits ONLY the three
hashes above for POST /api/chat, bodyless GET /api/version and /api/tags, and model-only
POST /api/show at 127.0.0.1:11434. No redirects or retries. Exact version/digest/
capability/thinking/default gates precede and follow each successful transport.
Conservative possibly_sent and request/generation/snapshot bindings are persisted
before the attempted launch, including spawn failure. The parent kills/reaps only its
own child on failure/interrupt; server-side cancellation is not guaranteed. Validation,
metadata, loading, generation, Chief review, saves, cleanup and seal share one monotonic
540-second deadline. No callback or storage wait extends the budget.

The accepted capped parser/replay is reused unchanged. Strict UTF-8/NDJSON shapes,
model identity, nonnegative integer counters, one terminal event at strict EOF, exact
chunk index, known-prefix timing and unknown-tail refusal all remain enforced. Only
stop/length terminal reasons are accepted. Errors, malformed/trailing bytes or events,
incomplete EOF, timeout, transport failure or unlogged raw tail stop later requests.
Keep raw flushed bytes, chunks, origin, headers, stdout/stderr, returned counts, partial
thinking/content/progress and process/deadline evidence. Raw thinking stays machine-only;
terminal/report output contains counts/times. Characters are never reported as tokens.

EVERY strict length terminal is CENSORED / INCOMPLETE / UNGRADED, including eval_count
4096 and content that parses as JSON. Preserve observed raw/progress and any returned
counter/cap-match evidence without inventing missing counters. Never decode, render,
meaning-grade or continue after length. A differing/absent length count is retained
honestly; it grants no continuation. This is not a wrong-answer grade. Post-identity
failure may additionally mark that slot failed. Length cannot complete this run.

A present stop eval_count above 4096 fails BEFORE decode/render/review/next request.
Absent stop counters are allowed; no counters are fabricated. Only a valid stop within
the cap reaches unchanged strict `work_review.decode` and saved-only `render_result`.
Save bound result.json and work-review.md before the REQUIRED bounded Chief callback
`assess(slot, result, deadline)`. Every render, including empty and final selections,
requires exact `{critical: bool, assessment: nonblank str}` with no other fields before
continuation. Missing/malformed/late/failed/critical verdict or review-save failure stops.
The accepted scoped SIGALRM boundary refuses non-main threads/existing timers and
restores the handler. The trusted Chief callback must honor the deadline and alarm.

Meaning is assessed independently against the original source under frozen
`evaluation/m10/reviewable-draft/work-review-schema-1-analysis/criteria.json`:

- First case: retain complete T1 undertaking and Next Tuesday timing in focused selection.
  Empty groups is a critical omission.
- Second case: retain surviving invoice sending with complete original undertaking and
  withdrawal context T1/T2 in a focused associated group; a human resolves currentness.
  Empty selection, lost surviving work or lost withdrawal context is critical.
- Third case: availability/status facts create no genuine undertaking. Empty groups
  are required to meet this criterion. Fact-only selection does not meet the criterion
  and adds noncritical review burden. Judge actual displayed meaning without
  automatically treating a selected fact as a claimed current task.

A generic notice, transcript dump, source-fidelity check or complete-source annex alone
cannot establish useful selected-work coverage. There is no semantic matcher, automatic
quality pass or currentness assertion. Complete original writing remains separately saved.

a valid terminal observation. Completion requires all three valid stop answers, gates,
required noncritical reviews and successful finalization within the deadline. No save,
seal failure or overrun permits an overall complete claim. All unsent bindings remain.
