## Commitment evidence and admissibility

Summary-stage action candidates identify their original transcript source and exact
undertaking/context anchors, a compact basis (explicit, third-person, accepted request,
implied or coordinated) and committed/uncertain disposition. Code assembles task, owner
and timing from source evidence. A declared basis/status is not independent proof.

Use source-anchored evidence and a narrowly documented diagnostic to detect descriptive
facts/status/predictions, proposals/questions, examples/quotations, negation and explicit
retraction. Do not use fixture strings or a first-person-only task whitelist. Preserve
supported third-person and implied undertakings as well as coordinated tasks and
conditional commitments. Check relevant same-speaker context for retractions without
erasing unrelated tasks or treating another speaker's disclaimer as cancellation.

Detected noncommitment selections trigger the existing correction. Candidates whose
admissibility remains uncertain are retained as attributed review evidence/warnings,
outside executable action checklists. Absence of a diagnostic is not proof of semantic
correctness. The implementation must document its recognized forms and limits.

Correction selection protects admissible commitments, timing evidence and independently
supported agreements. It must not protect an invented first-attempt task just because
its source ID exists. A blocked draft is never a valid fallback. Do not splice drafts.

## Anchors, spans and coverage

Resolve literal note-claim anchors against saved source passages; assign claim IDs in
source order. Require unique occurrence unless an explicit occurrence discriminator
selects a repeated literal. Reject absent/empty anchors, duplicate use, overlaps, reversed
order and uncovered semantic text. No fuzzy matching or silent normalization.

Code retains every intervening character rather than asking the model to reproduce
punctuation. Allowed residual gaps are whitespace/punctuation and narrowly defined
additive separators such as `, and `; save them as evidence. Negation, uncertainty,
alternatives, conditions and uncovered headings/facts/requests are not formatting.
Reject a gap containing such words unless covered by a claim anchor. Save offsets,
anchor text, retained gaps and complete original/effective input. Preserve inter-passage
text through the saved effective note and its source offsets. Text coverage cannot
prove atomic semantic splitting, qualifier attribution or entailment.

## Comparison and source separation

Distinguish consistent, conflicting, related-distinct, uncertain and unmatched additional
claims. Related-distinct accounts can retain transcript context without claiming the
same proposition agrees or conflicts. Different explicit periods/scopes can coexist;
unresolved estimate/approval and tentative/confirmed relations need visible review.
Shared quantities or keywords never mechanically establish identity or disagreement.

Preserve subject, quantity/unit, period, scope and epistemic status. Reject blank or
literal-null dimensions instead of accepting them as extracted meaning. Distinguish
absent information from unresolved extraction, using a compact representation. Do not
invent missing values or claim that populated fields prove semantic completeness.

Use a flat transcript-only reference vocabulary for generated spoken core/actions/timing.
Remove redundant generated notes/conflicts prose from the new draft; comparison owns
both accounts and code copies written context. Keep runtime kind/quote/numeric checks
on initial attempts, corrections and fallback. Generated spoken prose remains supported
prose rather than becoming fully extractive; wrong meaning with a valid T ID remains
a quality-evaluation concern and must have explicit negative tests where diagnosable.
